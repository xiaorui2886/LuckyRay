# LuckyRay Notes Live Markdown Editor

This directory owns the Obsidian-style Live Preview editor for the Notes page.

## Current direction

- CodeMirror 6 is the editor kernel.
- CodeMirror search is enabled in Live mode; `Ctrl/Cmd+F` should search within the current note editor, while global search stays on the app-level shortcut.
- Markdown `contentText` remains the only persisted source of truth.
- React/DOM widgets are visual decorations only. Never persist widget HTML.
- The old textarea is kept as the `source` fallback mode in `NotesPage.tsx`.

## Files

- `LiveMarkdownEditor.tsx`: React wrapper around CodeMirror. It exposes an imperative handle used by `NotesPage` for focus, selection, range replacement, and completion.
- `liveMarkdownExtensions.ts`: CodeMirror StateField decorations for Live Preview tokens.
- `assetEmbedWidgets.ts`: DOM widgets for `![[asset]]` and `[[note]]`.
- `blockWidgets.ts`: block widgets for Properties/frontmatter-adjacent Live rendering such as code fences and callouts. Widgets select the original Markdown block when clicked.
- `wikiCompletion.ts`: completion source for `[[note]]`, `![[asset]]`, and `#tag`.
- `noteAssetResolver.ts`: shared resolver for asset embeds. Preview mode and Live Preview should both use this to avoid different matching rules.
- `sameNoteAnchors.ts`: shared heading/block-id collector for same-note `[[#heading]]` and `[[#^block]]` completion.
- `liveMarkdown.css`: editor and widget styling.
- `types.ts`: narrow editor-facing data types, kept separate from bridge/database types.

## Invariants for future agents

1. Keep `contentText` as Markdown. Do not save card HTML or CodeMirror widget DOM.
2. Resolve asset embeds through the Knowledge Index and the canonical material resolver; ambiguous name/path matches must stay unresolved.
3. Use WebView-ready thumbnail URLs. Backend bridge results should run through the same URL conversion used by `listAssets()`.
4. Do not put large editor logic back into `NotesPage.tsx`; add small editor modules instead.
5. When adding a visual token, decide what happens when the cursor enters the token. If it cannot be edited safely, reveal the source text while the cursor is inside.
6. Source mode must stay usable as a rollback/debug path.
7. Task-list checkboxes are implemented as inline mark decorations plus a click handler. Do not replace `[ ]` / `[x]` with a widget; replacement disturbed continuous typing by shifting later input.
8. Dropped/pasted files are handed to `NotesPage` through `onInsertFiles` in Live mode and through the source textarea file handlers in source mode. The editor must not import files itself; `NotesPage` uses the bridge so the current material storage mode remains authoritative.
9. Block asset cards can resize by rewriting the Markdown token to `![[asset|width]]`. Keep the visible syntax user-facing; do not introduce hidden asset IDs until the note-link/index layer is ready for it.
10. Enter, Backspace, Tab, and Shift+Tab only customize behavior for Markdown list or task lines. Plain text should keep default editor behavior. Ordered-list Enter should renumber following same-level items, while nested child lists keep their own numbering.
11. Headings, quotes, lists, and tasks remain line decorations over the original Markdown. Preserve source editability unless a widget can select the original Markdown range and reveal source editing on click.
12. `NotesPage` keeps a short-lived `sourceContentDraft` when switching from Live to source mode. This prevents the source textarea from showing stale content after CodeMirror-only edits such as Tab indentation.
13. Keep placeholder and editable state in compartments so they can update when the selected note changes. The Live editor is mounted even when no note is selected.
14. Keep the CodeMirror cursor styled with the theme accent. The browser default can be black, which is effectively invisible in LuckyRay's dark editor.
15. Keep Knowledge Index relation parsing aligned with Live Preview parsing. `![[asset|width]]` is an embed relation, while `[[note#heading|alias]]` and `[[note#^block|alias]]` index the real document target only.
16. Tags become chip widgets only when the cursor leaves their line. While editing the same line, keep `#tag` as marked source text so ordinary typing, IME composition, and deletion stay predictable.
17. Same-note anchors such as `[[#heading|alias]]` and `[[#^block]]` resolve through the current note id in Live and preview modes. Do not index or display them as missing notes.
18. Same-note anchor completion is shared through `sameNoteAnchors.ts`. Source mode shows a popup for `[[#` / `[[#^`; Live mode can complete the current anchor token with Enter or Tab even when the CodeMirror tooltip is not visible.
19. Anchor clicks should call `findSameNoteAnchorRange` and select the source range inside the active editor when opened from Live/source context. Preview mode may still use the preview pending-scroll path so rendered preview highlighting remains intact.
20. Cross-note anchor completion also uses `sameNoteAnchors.ts`. Pass `contentText` into editor-facing note data so `[[note#...]]` and `[[note#^...]]` can complete against the target note without bridge round-trips. Keep anchor completion `filter: false` in CodeMirror because the typed text includes the note prefix while candidate labels are only anchor labels.
21. `luckyray:note-external-updated` must refresh the affected note in the `notes` list even when it is not selected. Cross-note completion reads `notes[].contentText`, so stale list state can make renamed/backfilled notes complete against old headings or blocks.
22. Live widgets expose `data-lr-token-*` metadata for interaction only. Right-click token menus should use the widget callback and token ranges to open/copy/remove the original Markdown reference; left-click handlers must ignore non-left mouse buttons so context menus can fire.
23. Note-link token menus must carry the same `LiveNoteOpenOptions` as double-click/Ctrl-open. `[[note#heading]]` and `[[note#^block]]` should keep the user in Live/source edit mode and select the target heading/block instead of opening the note at the top.
24. Creating a missing inline `#tag` from the Live token menu should also attach that tag to the current note metadata before opening the Tags page. Otherwise the visible chip and the note tag bar drift apart.
25. Creating a missing `[[note]]` from the Live token menu should use the parsed target title, not the display alias. For `[[NewNote|Alias]]`, create `NewNote` and then select the new note.
26. Creating a missing document should refresh the Knowledge Index so unresolved wiki targets, backlinks, and graph edges converge without another source edit.
27. Asset, note-link, and tag widgets should select their whole Markdown token on left click. CodeMirror's default Delete/Backspace then removes the selected token; do not add extra delete handlers unless this default path regresses.
28. Creating a missing anchored note should seed an editable anchor target. Use `# Heading` for `[[NewNote#Heading]]` and `待补充 ^block-id` for `[[NewNote#^block-id]]`, then open the new note with the anchor selected in Live mode.
29. Global tag rename and merge must update Markdown text as well as item-tag metadata. Keep inline `#tag` replacement out of inline code/code fences, and treat common Chinese punctuation as tag boundaries so `#标签。` does not become a different tag.
30. IME composition owns the keyboard while active. Keep automatic completion under manual control, close completions on `compositionstart`, and let Enter/Tab/Backspace fall through when `EditorView.composing` is true.
31. Frontmatter and code fences are parser exclusion ranges for Live widgets. Do not render `[[link]]`, `![[asset]]`, `#tag`, or inline emphasis widgets inside them; frontmatter may collapse to a Properties widget only while the selection is outside that block.
32. Code fences, callouts, and tables may collapse to block widgets only while the selection is outside their ranges. Clicking a block widget should select the original Markdown block and reveal source editing; never save widget DOM or synthesized text.
33. Formatting and mode-switch shortcuts in Live and source modes should delegate to `NotesPage` editor commands. Keep right-click commands, keyboard shortcuts, and editor mode buttons on the same path so Markdown wrapping, status text, source fallback, and preview/source switches stay aligned.
34. Live editor search uses `@codemirror/search`. Do not redirect `Ctrl/Cmd+F` to global search from inside the editor; global search remains app-level (`Ctrl+K`) so note-local find and app-wide search stay distinct.
35. AI writing shortcuts should open the same `NotesPage` AI write menu as the context menu. Commit the current editor draft before opening the menu so AI prompts read the latest Live/source content.
36. Related-note panels should parse the current Markdown for display-only alias and anchor metadata. Keep the database relationship target as the real note title, but show `[[Target#Heading|Alias]]` as `Alias` with target/anchor context in the panel.
37. Note completion rows should stay Obsidian-like: pass `folderPath` and `snippet` through `LiveNote`, and render Live/source completion candidates with title, path, and a short content excerpt. Do not regress `[[` completion back to title-only rows.
38. Editing a note-link display text from the token context menu rewrites only the current Markdown token to `[[target|alias]]`. It must not rename the target note or rewrite every backlink.
39. Source mode is a real fallback, not a bare textarea. Keep `Ctrl/Cmd+B`, `Ctrl/Cmd+I`, `Ctrl/Cmd+K`, `Ctrl/Cmd+Shift+K`, `Ctrl/Cmd+E`, `Ctrl/Cmd+Shift+E`, and `Ctrl/Cmd+J` aligned with Live mode unless a shortcut is explicitly moved.
40. Source mode context menus should detect Markdown tokens under the textarea cursor and pass the same `LiveEditorTokenContext` shape as Live widgets. Asset, note-link, and tag token actions must stay shared between Live and source modes.
41. Source mode must keep file paste/drop parity with Live mode. When clipboard or drop data contains files, prevent the browser default and call the shared asset import/insert path; ordinary text paste should remain native.
42. Preview and Live table parsing must use the shared helpers in `noteRenderer.ts`. Escaped pipes such as `a\|b` are one cell, not a column split; do not reintroduce ad hoc `split("|")` table parsing in editor modules.
43. When adding or exposing a formatting command, make sure Live decorations reflect the written Markdown syntax. For example, the existing strikethrough command writes `~~text~~`, so Live mode decorates it with `lr-live-strike`.
44. Preview inline formatting should stay aligned with Live formatting marks. Add token types in `noteRenderer.ts` and render styles in `NotePreview` whenever a command exposes Markdown syntax such as `**strong**`, `*emphasis*`, `` `code` ``, or `~~strike~~`.
45. Block style commands should transform the selected/current lines instead of stacking Markdown prefixes. Heading, paragraph, quote, unordered list, numbered list, and task list actions all go through `applyEditorCommand()`.
46. Inline formatting commands should be toggles, not one-way wrappers. Bold, italic, strikethrough, and inline code must remove existing surrounding marks when the selection is already formatted, and insert/select placeholder text when no text is selected. Keep `*`, `**`, and `***` boundaries distinct so italic does not strip bold, and bold does not strip italic.
47. Insert commands should leave the next editable placeholder selected. Table insertion selects the first body cell, callout insertion selects the body text, and code-block insertion selects the placeholder or the original selected text inside the fence.
48. Horizontal rules use the shared `isMarkdownHorizontalRule()` helper in preview and Live mode. A top `---` is frontmatter only when a closing frontmatter boundary exists; otherwise it should render as a normal horizontal rule once the cursor leaves the line.
49. Alignment commands currently use Markdown-compatible HTML blocks (`<div align="...">`). Preview must render those blocks with the requested alignment, Live mode should style the inner source lines, and the command should keep the wrapped text selected for immediate editing.
50. Empty Markdown list and task rows are still structural rows. Preview, Live decoration, and Live keyboard handling should treat `- [ ]`, `- [x]`, `-`, `- `, `1.`, and `1. ` as task/list rows rather than paragraphs while the user is drafting.
51. Completion keymaps have priority over list keymaps while a completion tooltip is active or pending. Enter/Tab/Shift+Tab should accept or navigate completion first; only fall back to anchor completion and list editing when no completion is open.
52. Missing-note creation from Live widgets, source-token menus, and preview links must pass anchor options through the create path. `[[New#Heading]]` should create `New` with a seeded heading, and `[[New#^block-id]]` should create `New` with the block id rather than a blank note or a note literally named with the anchor.
53. Note title rename must keep Obsidian-style wiki references coherent. The bridge rewrites matching Markdown `[[Old]]`, `[[Old#Heading|Alias]]`, and `[[Old#^block]]` tokens to the new title, skips asset embeds, resyncs relation rows for changed source notes, and the active note reloads its relationship panel after a title save.
54. Live note-link hover/focus tooltips are display-only DOM inside the widget. They may show target title, folder path, heading/block anchor, alias, and open/create hints, but must not change the saved Markdown token or intercept context-menu selection.
55. Backlink snippets should prefer parsed wiki-link display text over raw Markdown. A backlink through `[[Target#Heading|Alias]]` should show alias, target, and anchor context in the index panel; fall back to text excerpts only when there is no matching wiki token.
56. Code-block widgets may offer display-only commands such as copy. Those controls must stop event propagation so clicking them does not select the Markdown block; clicking the rest of the widget should still select the original fenced code source.
57. Callout tone classes should apply in both collapsed widgets and source-line decorations. Keep `kind-tip`, `kind-warning`, `kind-danger`, `kind-success`, `kind-question`, and `kind-quote/example` visually distinct while preserving the original Markdown source and block-selection behavior.
58. Preview callout styles should stay aligned with Live callout styles. When adding or changing a callout tone, update both `liveMarkdown.css` and `notes.css` so Live, source-line decoration, and read-only preview do not drift.
59. Table widgets may expose display-only controls such as copying the table source. Copy actions should read the exact Markdown range from the editor document and stop event propagation; clicking the rest of the widget should still select the original table source.
60. Properties/frontmatter widgets may expose display-only controls and overflow summaries. Copy actions should read the exact frontmatter Markdown range from the editor document, and any summarized row must remain visual-only; clicking the rest of the widget should still reveal the original YAML source.
61. Any bridge/search result that feeds note asset cards, completion rows, or global search thumbnails should return WebView-ready URLs. In `App.tsx`, select `library_path` with `thumbnail_url` and pass both through `derivePreviewUrl()` instead of returning raw database paths.
62. External Markdown links (`[label](https://...)`) are visual Live widgets only when the cursor is away from the link line. Plain click should select the original Markdown token for editing; Ctrl/Cmd-click may open the URL. Do not persist anchor HTML.
63. Dropped or pasted files should insert asset embeds as Markdown block references. When the drop point is inside existing text, add blank-line padding around the generated `![[asset]]` lines so Live/Preview render material cards cleanly instead of merging them into a paragraph.
64. External-link context menus should stay shared between Live widgets and source textarea detection. Both modes should pass `kind: "external"` with the original Markdown range and href so open, copy, and remove actions operate on the same token span.
65. Editing link display text should preserve Markdown as the source. Wiki links rewrite to `[[target|alias]]`; external links rewrite to `[title](https://...)` and should validate that the URL remains http/https before saving.
66. Global tag delete, tag-detail removal, and graph note-tag disconnect should keep Markdown `#tag` text in sync with item-tag metadata. Remove matching inline/frontmatter tag references outside inline code and code fences, then notify open notes through `luckyray:note-external-updated`.
67. Knowledge-index outgoing links should combine database relation rows with the current Markdown token metadata. The relation table stores the target title only; parse `[[note#heading|alias]]` and `[[note#^block]]` from `contentText` so list labels, meta text, click navigation, and missing-note creation preserve alias and anchor behavior.
68. Anchor completion should preserve an already typed wiki-link alias suffix. Completing `[[Note#hea|Display` must produce `[[Note#Heading|Display]]`, and completing `[[#hea|Display` must produce `[[#Heading|Display]]` in both Live and source modes.
69. Controls inside Live widgets must stop `mousedown` as well as `click`. Buttons such as asset-card open/remove or block copy actions should not bubble to the parent widget and select the underlying Markdown token before their own action runs.
70. Removing an inline tag token from the editor should not leave note tag metadata stale. After deleting the token, check whether the same tag still exists in Markdown/frontmatter outside code; only detach the note-tag relation when no matching reference remains.
71. Saving a note should merge frontmatter `tags` and inline Markdown `#tag` references into note-tag metadata in both SQLite and browser fallback modes. Extraction must ignore frontmatter body, fenced code, and inline code; explicit remove/delete flows remain responsible for detaching stale relations.
72. Inline tag parsing must keep Live widgets, save-time extraction, rename, delete, and relation-detach checks on the same boundary rules. Common Chinese punctuation and full-width brackets should end a tag instead of becoming part of the tag name.
73. Relation indexing for `[[note]]` and `![[asset]]` should skip frontmatter, fenced code, and inline code just like Live widgets do. Example syntax inside code samples must not create graph, backlink, or asset-embed rows.
74. Unlinked mention scans should use the same relation-exclusion text as link/embed indexing. A target title that appears only in frontmatter, fenced code, or inline code should not show as an unlinked mention.
75. Block asset cards should preserve the referenced media's visual shape. Use thumbnails as posters/covers, `previewUrl` for video hover playback, and keep open/remove controls plus resize handles quiet: open/remove should match the original compact 24px hover buttons, and resize should be an image-only 18px corner affordance rather than a prominent round button.
76. Menu-driven insert asset/wiki-link commands should open the Obsidian/original-style insert picker, not the compact CodeMirror completion tooltip. The picker should stay close to the original 400px confirm dialog, require a visible selected row before insertion, and keep typed `![[`, `[[`, and `#` completion available for fast keyboard input.
77. Rename backfills for notes and assets must use the same Markdown exclusion ranges as relation indexing. Do not rewrite `[[note]]` or `![[asset]]` examples inside frontmatter, fenced code blocks, or inline code; only real prose references should be updated.
78. Preview-mode task checkboxes should still write Markdown, not DOM state. Toggling a rendered task updates the matching `- [ ]` / `- [x]` source line and flows through the normal note save path; split preview may stay read-only unless it owns a safe save path for that note.
79. Preview-mode asset media should distinguish image and video sources. Do not feed a video `previewUrl` into an `<img>`; render videos as muted poster-backed media that can hover-play, matching the Live asset-card behavior.
80. Asset media thumbnails in insert pickers should use the same image/video distinction as preview cards. A video-only `previewUrl` must render as video media or a safe fallback, never as a broken image thumbnail.
81. Asset media thumbnails in both Live CodeMirror completion and source-mode fallback completion must use the same image/video distinction as preview cards. Typed `![[` completion should never feed a video `previewUrl` into an `<img>`.
82. Knowledge-index asset thumbnails should reuse the same asset media rendering path as preview cards and insert pickers. The right-side referenced-assets panel must not special-case video assets back into `<img>` thumbnails.
83. Clipboard image handling stays split by responsibility. Editor modules may detect `text/html`, `text/uri-list`, plain image URLs, or `data:image/*` clipboard sources, but `NotesPage` must perform the actual asset import through the bridge and insert a Markdown `![[asset]]` reference.
84. Dragging an existing material asset from the material library into a note is an internal reference operation. The material card writes only a lightweight drag payload, Live/source editors read that payload, and `NotesPage` inserts `![[asset]]`; external files still go through the bridge import path so material storage mode remains authoritative.
85. Preview and Live Properties views should keep frontmatter visual-only. Copy buttons copy the original frontmatter Markdown, long values are summarized as chips with `title` tooltips, and clicking the body still returns users to the editable YAML source instead of mutating rendered rows.
86. Manual completion should stay available in both Live and source modes. `Ctrl+Space` opens the same `[[note]]`, `![[asset]]`, `#tag`, and anchor completion paths as automatic triggers, so users have a fallback when timing, IME state, or cursor movement prevents the popup from appearing.
87. Callout folded state is Markdown-driven. `> [!type]- Title` renders the callout header only in Live and preview modes, while `> [!type]+ Title` and plain `> [!type] Title` render the body; clicking the widget still reveals the original Markdown source.
88. Live table cells are editable table controls, not display-only inline Markdown. Keep the rendered table widget visible even when the editor selection maps into the table source range, and commit transparent cell editor changes back to the matching Markdown table cell without revealing the whole source table in Live mode.
89. Preview code blocks may expose a copy button for the code content, matching Live code-block behavior. The preview control is display-only and must not mutate Markdown or interfere with returning to Live/source editing.
90. Preview tables may expose display-only controls such as copying the table Markdown. Copy actions should use the original Markdown source captured by `noteRenderer.ts`, not DOM text reconstructed from rendered cells, so escaped pipes, alignment rows, and block ids stay intact.
91. Live block ids such as `^block-id` should render as quiet inline anchors, but remain plain editable Markdown. Do not replace them with widgets; same-note and cross-note `#^block-id` links still use the shared anchor completion/navigation path.
92. Notes-page Markdown import/export controls should call the existing bridge methods instead of parsing files in the editor. Import refreshes notes and opens the first imported note in Live mode even if the previous note was in source/preview; export delegates to the data layer so future attachment handling can stay centralized.
93. Markdown export should keep database notes unchanged while producing portable files. Referenced material embeds are copied to an `exports/assets/` folder when the source file is available, and exported Markdown rewrites only prose `![[asset]]` tokens to relative `![[assets/file]]` targets while leaving frontmatter and fenced code samples untouched.
94. Markdown import should recognize Obsidian-style local attachments without bypassing material storage rules. Relative wiki embeds such as `![[image.png]]`, exported `![[assets/image.png]]`, and Markdown images such as `![](image.png)` may import the matching local file through the material import bridge, then rewrite prose references to LuckyRay `![[asset name]]`; missing files, frontmatter, and fenced code examples must remain unchanged.
95. Source fallback must follow the same IME rule as Live mode. During composition, keep saving the textarea value but close/suppress `[[`, `![[`, and `#` completion popups; recompute completion only after composition ends so Chinese input does not fight the autocomplete layer.
96. App-level shortcut handlers must respect editor-owned key events. If Live/source shortcuts such as `Ctrl/Cmd+Shift+K` prevent the event for an editor command, `AppShell` should not reopen the command palette or global search on the same keydown.
97. Desktop-level global shortcut registration must stay stricter than in-app shortcuts. Plain editing accelerators such as `Ctrl/Cmd+K` belong to the editor and window keydown path; only Alt-based or function-key combinations should be registered through the Tauri global-shortcut plugin.
98. Note relation loads are selection-scoped async work. Tags, backlinks, outgoing links, embeds, referenced assets, and AI suggestions should only update the panel for the latest relation request; closing the final tab must invalidate pending relation responses so stale suggestions cannot reappear.
99. Note selection loads are also selection-scoped async work. `selectNote()` must guard `getNote()`, relation refreshes, delayed anchor selection, delayed editor focus, and delayed list scrolling with the same latest-request check so fast tab/sidebar/link navigation cannot show one note's title with another note's body.
100. Source-mode drafts are scoped to the selected note. A successful note selection or an empty editor state must clear `sourceContentDraft` and source fallback autocomplete so one note's textarea draft cannot appear under another note after fast sidebar, tab, or wiki-link navigation.
101. Pending autosave patches are scoped to the current note even though `pendingPatchRef` is shared. Before `selectNote()` changes away from the active note, flush the current save timer through the existing save path so edits to note A cannot be merged into a later save for note B.
102. AI write requests are scoped to the note id and content snapshot used to build the prompt. If the selected note changes or the editor content changes before the model response returns, discard the write-back and surface a status message instead of applying the stale replacement range.
103. AI tag suggestions are scoped to the note id that generated them. Store the note id with the suggestion, ignore late suggestion responses after navigation, and refuse to apply tags if the visible suggestion no longer belongs to the selected note.
104. AI read paths should use the active editor value, not just the last React `editContent` snapshot or SQLite row. Before generating note AI suggestions, flush the current title/content to the note save path; when opening the AI assistant with note context, read `readActiveEditorValue()` so unsaved Live/source edits are included.
105. Inline code is a semantic exclusion zone for Live Preview widgets and preview tokens. Text such as `` `[[note]]` ``, `` `![[asset]]` ``, or `` `#tag` `` must stay code text instead of turning into wiki links, asset cards, or tag widgets, while the code styling itself still renders normally.
106. Same-note anchor completion and navigation must use the same Markdown exclusion idea as rendering. Do not collect headings or block ids from frontmatter, fenced code blocks opened with either ``` or ~~~, or other non-prose regions that should not create real wiki anchors.
107. Fenced-code tracking must be marker-specific across rendering, indexing, tag sync, and Markdown import. A code block opened with ``` only closes with ```, and one opened with ~~~ only closes with ~~~; mixed fence examples inside code must not leak wiki links, asset embeds, tags, or local attachments into real metadata.
108. Completion trigger detection must use the same prose-only boundary as rendering and indexing. Live CodeMirror, manual anchor completion, and source textarea fallback should not open `[[`, `![[`, or `#tag` suggestions inside frontmatter, fenced code blocks, or completed/currently open inline code spans.
109. Table cell parsing must not split on pipes that belong to inline code, wiki-link aliases such as `[[note|alias]]`, asset width syntax such as `![[image.png|320]]`, or Markdown link labels/URLs. Only unescaped pipes outside those protected inline regions are table separators.
110. Ordered-list continuation should renumber after both insertion and exit. Pressing Enter on a non-empty `1.` item inserts `2.` and pushes later same-level siblings forward; pressing Enter on an empty `2.` item removes that marker and pulls later same-level siblings back to `2.`.
111. Source fallback should keep list indentation aligned with Live mode without taking over plain text. When no completion is active, Tab/Shift+Tab may indent or outdent selected Markdown list/task/ordered-list lines in the textarea; non-list prose should keep the browser default.
112. Source fallback should also mirror Live list Enter/Backspace behavior when no completion is active. Enter may continue a list item or exit an empty item, and Backspace at the item content start may outdent or remove the list marker; selections and plain prose should keep textarea defaults.
113. Removing an ordered-list marker with Backspace should renumber following same-level ordered siblings in Live and source modes. Nested child lists may keep their own numbering, but later `3.` at the removed item's level should become `2.`.
114. Tab/Shift+Tab on ordered-list items should renumber the affected old and new sibling runs in Live and source modes. Moving `2. B` under `1. A` should pull the old-level `3. C` back to `2. C`, and the moved child run should start at `1.` when it has no previous same-level sibling.
115. Source-mode token context menus must use the same prose-only exclusion as completion and Live widgets. Right-clicking `[[note]]`, `![[asset]]`, `[url](...)`, or `#tag` inside frontmatter, fenced code, or inline code should show the normal editor menu, not a semantic token menu.
116. Preview-mode wiki links should resolve against the current Knowledge snapshot. A newly typed `[[Existing Note]]` should not look missing solely because an async index refresh is pending; matching should use normalized document titles like Live/source.
117. Outgoing-link display metadata should only come from prose links. The helper that extracts aliases and anchors for the right-side outgoing list must ignore `[[note|alias]]` tokens inside frontmatter, fenced code, and inline code so code examples cannot override the visible label or jump target of a real relation row.
118. Live external-link widgets must expose the same token context menu as source mode. Right-clicking `[title](https://example.com)` in Live mode should select the original Markdown range and offer open, edit, copy, and remove actions through the shared external-link token path.
119. Asset token menus should distinguish between copying the plain material name and copying the Markdown embed. `复制素材名` writes only the visible asset name, while `复制 Markdown 引用` writes the original `![[asset]]` source range.
120. Asset token primary menu wording should match the actual navigation behavior. The shared token opener focuses the asset in the material library, so the Live/source asset menu should say `定位到素材库` instead of implying an in-editor asset reference opens separately.
121. Tag token rename should use the existing tag bridge, not a local string-only rewrite. Before renaming a `#tag` from the editor menu, save the active editor draft, then call `updateTag`/`renameTag` so Markdown tag references and note-tag metadata stay synchronized through the data layer.
122. Asset token open and locate are separate actions. `定位到素材库` should only focus the material card, while `打开素材详情` should pass a `detail` nav-focus action so Materials opens the inspector for that asset.
123. Preview-mode inline tags must come from the shared inline renderer. `parseNoteInline()` should emit `tag` tokens for prose `#tag` text outside inline code, and `NotePreview` should render those tokens as small clickable chips using the current tag list instead of ad hoc scanning rendered strings.
124. Token menus should keep target copying separate from Markdown copying. `复制链接目标` copies a wiki link without the display alias, `复制链接地址` copies only the external href, and `复制 Markdown 引用` still copies the exact original token range.
125. `在新标签打开` for note-link tokens should add the target note to `openTabs` without selecting it. This keeps the current editor context intact while making the linked note available in the top tab strip; normal `打开笔记链接` remains the foreground navigation action.
126. `编辑笔记引用` should edit only the current wiki-link token, not rename the real note or rewrite other notes. The dialog may change the token target (`[[Note#Heading]]`) and display alias (`|Alias`), but it must reject empty targets and unsafe closing-bracket/newline characters before replacing the Markdown range.
127. Missing wiki links in Live mode should keep normal click as token selection, but `Ctrl/Command + click` and double-click should both create the missing target. This matches existing-link modifier-click behavior without causing accidental navigation while editing prose.
128. Editor commands must read from the active editor document, not the last React state snapshot. Right-click commands and keyboard shortcuts should call `readActiveEditorValue()` before applying Markdown transforms so freshly typed Live/source text is included even before React state or autosave settles.
129. Published note context should also come from the active editor document. `publishActiveNoteContext()` feeds AI/global context, so it should slice selections and publish `contentText` from `readActiveEditorValue()` with range clamping instead of trusting `editContent`.
130. The direct `发送到 LightSeek` note handoff should preserve the selected text when present and otherwise use a bounded document summary. Stage it through the single app-owned `OpenInLightSeekIntent`; the official DSH consumer may only call `InputActions.setDraft`, never auto-send or create a second session/history truth.
131. AI-page writes back to the active note should respect the editor cursor when possible. Use `insertIntoCurrentNote({ text, appendIfNoCursor: true })` for the active note, and fall back to append-only updates only when the cursor/local API path is unavailable.
132. Graph body relation editing must share the same prose-only Markdown rules as Live Preview and completion. Connect/disconnect should ignore wiki links and asset embeds inside frontmatter, fenced code blocks, and inline code so graph operations never treat examples as real note relationships.
133. Graph web-url extraction should also be prose-only. URLs inside frontmatter, fenced code blocks, or inline code are examples/metadata, not user-authored relationship edges, and should not create graph web nodes.
134. Source-mode context menus should use the right-click point, not only the textarea's previous caret. Preserve an existing text selection when the click lands inside it, but detect asset/wiki/tag/external tokens at the clicked position so source fallback stays aligned with Live mode's `posAtCoords` behavior.
135. The right-side knowledge index should read the active editor content, not a stale React snapshot. Outline, word/line counts, outgoing-link display metadata, and outline jump ranges should stay aligned with Live/source edits before autosave or relation refresh catches up.
136. Source-mode same-note anchor completion should read the active editor content. `[[#heading]]` and `[[#^block]]` candidates for the current note must include unsaved source textarea edits, while cross-note anchor completion may still use the target note's saved content.
137. Backlink snippets should use the same Markdown exclusion ranges as relation indexing. A prose backlink should not display an alias or excerpt from a frontmatter value, fenced code sample, or inline code example that happens to mention the same target earlier in the note.
138. Backend Knowledge Index parsing should match the frontend prose-only relation rules. It must skip frontmatter, fenced code, and inline code for both `[[note]]` and `![[asset]]`, and deduplicate repeated prose targets so backlinks, graph edges, and asset embeds do not drift from Live/source behavior.
139. Tab navigation must commit the active editor draft before changing the selected note. Closing the active tab, switching tabs, or selecting another note should push the current Live/source value through the normal save queue and flush it before clearing or loading a different note, so the last autosave window cannot drop edits.
140. Async save callbacks are scoped to the note they saved. A save for note A may update note A in the local list after the user navigates to note B, but it must not refresh the visible relation panel, active title event, status text, or saving indicator for B.
141. Live asset cards and table widgets must not use normal click to create large full-token or full-block selections. Asset cards place the caret before or after the Markdown embed, table cell clicks place the caret in the matching source cell, and token context menus receive token ranges without forcing a visible whole-token selection. Keep the editor selection background low-contrast enough that selected text remains readable.
142. A block asset card should stay rendered when the caret is at the embed token boundary. Only reveal the raw `![[asset]]` source when the caret is inside the token text or an explicit token edit action selects it; otherwise clicking before/after the card should preserve the card and keep following prose visible. Editor context-menu commands must use the selection captured when the menu opened, not a later focus-shifted editor selection.
143. Menu-driven insert pickers should separate hover from selection. Mouse hover may use CSS hover feedback, but only a click, keyboard ArrowUp/ArrowDown, or an explicit confirm should change `selectedIndex`, so moving from a chosen row to the Insert button cannot silently switch the target. Block asset card clicks should use vertical before/after positioning, and editor multi-selection backgrounds should remain transparent when the user wants text readability over selection tint.
144. Asset-card context menus should update the caret to the clicked before/after side without selecting the whole embed token. General editor commands launched from that menu should use the right-click position, while token actions still receive the original Markdown range.
145. Plain Live-editor clicks should use `EditorView.mouseSelectionStyle` to produce the precise selection before CodeMirror's default block-widget boundary mapping can draw a transient wrong caret. The style captures the mousedown `.cm-line` range, accepts native text-node positions only when their coordinates match the click, and otherwise scans that DOM line range's `coordsAtPos()` caret boundaries. Keep this limited to non-widget, non-control clicks so task toggles, token widgets, and block widgets keep their own handlers.
146. Live and preview table rendering should read as inline document content, not as a tool card. `TableBlockWidget` and `NotePreview` should render the actual table without a persistent meta toolbar, copy action, or standalone widget menu. CSS must keep the default table compact like Obsidian, with visible thin borders, transparent cells, and caret-only cell focus; table cell textareas must override note-level textarea padding/width/height so they cannot inflate rows or columns. Clicking anywhere inside a table cell, including empty cell padding, should focus that cell editor instead of placing the editor caret before/after the table. Live mode must keep table blocks rendered as widgets instead of revealing the whole Markdown table source. Table-specific row/column/sort commands belong in the shared editor context menu only when the right-click target is inside a table, placed after the normal `select-all` item, and should perform real Markdown-table edits: row add/move/copy/delete, column add/move-left/move-right/alignment/copy/delete, and current-column ascending/descending sort. Before applying a table command, recompute the current table source range from the active editor text so right-clicking after an unsaved cell edit cannot use a stale widget range. Lightweight Obsidian-like handles may appear on hover: row/column handles select contiguous rows/columns and copy selected cells as tab-separated text, while edge plus buttons append a row below or a column to the right by rewriting the Markdown table source.
147. Inserted table snippets should start as Obsidian-like blank 2x2 tables rather than labelled examples. Place the caret in the first blank cell so users can immediately type real content without deleting placeholder headers or body text.

148. At an exact rendered attachment boundary, Backspace/Delete first selects the complete reference while retaining the media preview and selected outline. The next delete key uses CodeMirror's ordinary selection deletion. Blank lines and prose keep normal editing behavior; a caret or partial selection inside an attachment still exposes source. Use existing decorations for boundary lookup, preserve IME ownership, and keep the same media node when only selection feedback changes.
